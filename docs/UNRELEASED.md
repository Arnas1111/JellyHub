# Profiles and server browsing — dev release batch

## Offline users and shared chat

- Added a separate muted Offline group with grayscale avatars. Enabled Jellyfin accounts are read from the native account directory, briefly cached and matched against recent sessions. Disabled accounts are excluded. When native visibility is incomplete, unconfirmed users are gray under Other users with unavailable status. Offline accounts do not contribute to the Online count. Sidebar scrolling is preserved across updates.
- Added Chat navigation and one shared room for signed-in users, with plain-text messages, display names, timestamps, Enter/Shift+Enter behavior and three-second revision-based updates while visible. Existing content is updated by message ID without repeatedly rebuilding the log. The latest 200 messages are saved atomically to `/config/chat.json` with private file permissions.
- Users can delete their own messages; current administrators can delete any message. Native account/role checks protect every chat request. Authenticated sender identity is assigned server-side, payloads are bounded, posts are rate-limited, retries are idempotent within retained history, and message text is escaped. Raw account IDs and retry IDs are omitted from browser responses.
- Drafts survive navigation, failed sends preserve their text, and drafts are cleared on logout. Storage/read errors are surfaced and corrupt history is preserved rather than overwritten. Native account authentication failures remove the invalid JellyHub session so revoked accounts cannot keep appearing active through denied chat/presence polls.
- Local validation covers concurrent writes, retention, restart persistence, retry deduplication, own/admin deletion, corrupt history, two-browser message delivery, literal markup, failed-send retry, mobile layout, offline styling and disabled-user exclusion with simulated Jellyfin. No existing backend containers were modified; deployment behavior still needs live verification.

## Sidebar online users

- Added a Discord-inspired Online list under sidebar navigation: circular avatars/initials, status dots, display names and watching/paused activity. One row represents one user across multiple devices and Jellyfin GUID formats; active playback takes priority over a paused second device. Rows link to media only when the viewer has Active Streams permission and item access.
- Online is based on recent requests/check-ins. Idle connections become Away after two minutes and are omitted after five minutes. Expired sessions, anonymous clients and invalid/future timestamps are excluded. The list is capped at 100 rows with an explicit shown count when necessary.
- Native session discovery uses the configured server-side service credential where available, with brief caching and recent JellyHub sessions merged in. Without server-wide access, a partial-scope hint is displayed. Stream titles require permission/media checks; non-admins cannot see forbidden titles even when the native source returns them.
- Avatar routes require sign-in and opaque recent-member identifiers. Image fetches are bounded, authenticated server-side and cached; missing pictures fall back to initials. Tokens, session IDs, IP addresses, paths and emails are excluded from the public presence payload.
- The existing 15-second sidebar refresh also updates presence, stops work when hidden and clears state on logout. Unchanged responses preserve the current member markup and decoded pictures. Mobile uses horizontal member scrolling. Docker packaging and smoke asset checks include the new server/browser modules.
- Tests cover grouping, stale/away states, partial outage fallback, title permissions, forbidden media, two concurrent signed-in browsers, real image decoding, live refresh, media navigation, logout removal and mobile width using simulated Jellyfin. The desktop sidebar screenshot was visually inspected; live server validation remains pending.

## Registration wording and default permissions

- The visitor form says only “Registration key”; format, rotation and credential-requirement hints are removed. Invalid keys use a plain error without describing expiry or length. Key generation and rotation continue server-side.
- JellyHub no longer applies username patterns or password length/complexity rules. Short names, spaces, Unicode and short or blank passwords pass unchanged to Jellyfin. Sign-in accepts blank passwords too. Existing names are checked case-insensitively before creation. Native Jellyfin account-store validation still applies, and JSON type checks, request-size limits, origin checks, rate limits and invite-key verification remain enforced.
- Administration → Registration now configures default Jellyfin permissions, server-section access and Requests/Active Streams access. Administrators can also require activation. Defaults persist in `/config`, merge correctly across partial settings updates, apply only to future accounts and are not accepted from the visitor's registration payload. Defaults retain previous behavior until edited. Administrator and disabled defaults cannot be combined because Jellyfin rejects that combination.
- Account setup still uses a random temporary password and a disabled, non-admin policy while initialization is incomplete. The configured administrator/activation state is applied last. Visitors requiring activation receive an appropriate completion message.
- Validation covers unrestricted credential forwarding, case-insensitive duplicate rejection, saved/default/partial permissions, short and blank-password browser signup/sign-in, plain form text and existing flows using simulated Jellyfin. Live service behavior remains subject to deployment validation.

## HTTP LAN compatibility hotfix

The filter controls and custom navigation no longer require `crypto.randomUUID`, which is unavailable on ordinary HTTP LAN origins. UI IDs use `crypto.getRandomValues`, which works there. The browser regression suite now uses a non-loopback HTTP hostname and explicitly checks that the secure-context-only API is absent before exercising Movies, TV Shows, My List, filters and collections. The original failure was reproduced in that environment before applying the repair.

## Seeking and manual previews

- The player keeps a drag's selected position steady until release, instead of allowing playback time updates to overwrite it. Keyboard seeking also commits the chosen position. Resume positioning runs once per stream, and progress is reported after a seek finishes.
- “Watch preview” uses the authenticated playback pipeline for direct play or Jellyfin HLS remuxing/transcoding, at up to 6 Mbps. It plays a 20-second excerpt from the server's media, with sound and native video controls; it is not an externally sourced trailer. Closing, ending or leaving the preview cleans up the stream and any encoding. Preview tickets cannot send watched/resume updates to Jellyfin. Background carousel previews retain their lightweight direct-play path.
- Regression validation uses actual MP4/HLS decoding against simulated Jellyfin. The drag regression fails against the old player (8.4 seconds overwritten with 3 seconds) and passes with the repair. Checks cover forward/backward dragging in direct/HLS playback, keyboard seeking, repeated metadata, preview decoding, cleanup and watch-state isolation. Live server playback still requires a user retry.

## Home and visual polish

### Requests and Active Streams update

Follow-up: Active Streams is always shown in navigation. Its dark count inside an orange notification badge updates every 15 seconds on authenticated pages, independently of detail-view permission. A disabled button and explanatory tooltip prevent entry without permission, while direct detail API requests remain denied. The separate count endpoint returns only `{count}` and preserves Jellyfin's caller-specific session visibility. Counts are cleared on logout, zero or unavailable counts hide the badge, and in-flight responses cannot update a later login's count. Regression checks cover a locked entry with a visible orange `1`, count updates to `2`, and count access without detail access.

- Removed the extra “On this server” headings. Requests is a dedicated navigation section with All Requests and My Requests; request history has moved out of My List. Existing `#favorites?source=requests` links redirect to My Requests.
- Requests includes active download progress, sizes and ETA when known, requester display names/initials, media details/play actions, status filters, release dates and paged coming-soon results. Seerr's verified actor and view-request permissions determine whether All Requests can include other users. My Requests always checks ownership. Private download filenames, IDs, API keys and requester email addresses are omitted.
- Coming-soon queries scan at most 250 source rows per continuation page. Active downloads cover the latest 100 processing requests, with a visible limit notice when applicable. Metadata caching and four-worker enrichment bound upstream work.
- Active Streams uses native Jellyfin session data for paused/playing state, position/duration, direct play/stream/transcoding, codecs, bitrate, resolution, frame rate and reasons for transcoding. It is read-only; no remote-control or administrator permissions are granted. Non-admin media access is checked before including a stream. Jellyfin normally limits non-admin session queries to that account's own sessions.
- Administration → Users has separate per-user Requests and Active Streams toggles saved in `/config`, preserving profiles and preferences. Requests defaults on for existing users; streams defaults off; administrators inherit access. Requests disablement covers request submission, catalog/discovery and their navigation; ordinary media search and favorites remain independent. API denial is immediate, including already-open streams pages on their next refresh. Browser reload updates navigation.
- Both pages refresh every 15 seconds while visible and release their timers on navigation. Failed refreshes retain prior stream/request data with an error; permission denial removes it. Server-side integration failures identify unavailable sources.
- Validation: syntax checks, 39 Node checks (38 passing on Windows and one POSIX-only skip) and eight browser suites. New cases exercise plain HTTP, All/My visibility, coming-soon continuation without duplicates, byte/ETA sanitization, persistent feature toggles, API denial, stream media filtering, admin revocation, live refresh and mobile width. Desktop screenshots were visually inspected. Actual Jellyfin/Seerr services are not available in this workspace.

API contracts were checked against [Seerr permissions](https://github.com/seerr-team/seerr/blob/develop/server/lib/permissions.ts), [Seerr request filtering](https://github.com/seerr-team/seerr/blob/develop/server/routes/request.ts) and [Jellyfin session visibility](https://github.com/jellyfin/jellyfin/blob/master/Emby.Server.Implementations/Session/SessionManager.cs).

- Cards use a green circled check for **On server**, an indigo circled plus for **Discover**, an amber clock for **Requested**, and a blue service mark for **Managed by Seerr**. Text and icons distinguish states independently of color. Managed-by-Seerr does not imply that the viewer has access to the item in Jellyfin.
- Native horizontal/vertical scrollbars use a dark track, rounded accent-colored thumb, hover treatment and no arrow buttons in Chromium/WebKit. Firefox uses the standard scrollbar-color/width styling. Keyboard, wheel and touch scrolling remain native. Forced-color mode uses system colors.
- Home restores the last featured selection and a compressed artwork snapshot from per-user session storage, before the featured refresh finishes. The cache keeps at most eight sanitized titles and one JPEG, expires after an hour and is cleared on sign-out/authentication failure. Stream URLs, credentials and user playback data are never serialized into it. First visits, expired caches and blocked storage use the existing stable loading stage.
- Cached slides remain static until a successful server refresh. A temporary service failure keeps the last frame and retries after 30 seconds. A fresh empty selection or authentication denial removes the snapshot. Hourly refresh retains the selected title when still present.
- Snapshot encoding is bounded to 1280 × 720 and avoids repeatedly recompressing cached JPEGs. Storage errors fall back to metadata-only snapshots or ordinary loading.

## Server language, browsing, profiles and personal lists

- User-facing media labels now say **On server**, **On this server** and **Server media**, without implying that the viewer owns the host's media. Internal Jellyfin API names retain their original identifiers.
- **Collections** is a horizontal subsection of **Movies**, alongside **All movies**. It is removed from the main sidebar and does not appear under TV Shows. Existing collection deep links remain usable, with Movies highlighted in navigation.
- Search occupies most of the browse toolbar. Small themed sort and direction controls sit beside it; watch/genre/year/server-section filters are in a styled dialog with keyboard-accessible custom option lists and removable active-filter chips. Native select dropdowns are no longer used in that toolbar.
- The upper-right name/photo button opens Profile. The current identity header stays visible while settings load and profile data is prefetched on hover. There is no intermediate “Your account” heading.
- Display names are stored per JellyHub user and shown in the header/profile and native community-review author names. They do not rename the Jellyfin login or overwrite another user's identity. Other Jellyfin clients continue to use Jellyfin's account name.
- Profile photos are read from and written to Jellyfin's own user-image API using the caller's token. Users can upload an image, choose a shared portrait, generate a colored initials avatar, or remove their picture. Existing password controls remain in Profile. JPEG/PNG/WebP uploads are validated and bounded; client uploads are center-cropped to 512 × 512. Existing GIF profile pictures can be read.
- JellyHub creates `/config/profile-pictures` and a short README when the updated app starts. With the default template this maps to `/mnt/user/appdata/jellyhub/profile-pictures`. The host can add PNG/JPEG/WebP choices there (maximum 2 MiB and 4096 × 4096); ordinary users choose from them in Profile. Symlinks, subfolders and unrelated files are ignored. This folder has only been created in isolated local test appdata so far; no Unraid container was changed.
- Maintainerr's collection `mediaServerId` values identify management collections, including inactive collections. Those IDs are saved in appdata, excluded from normal Collections for everyone, and blocked on direct media/image/detail routes for non-admins. Admins have a management-only list under Administration → Maintainerr. The last known IDs remain effective if Maintainerr or config persistence is temporarily unavailable. This changes JellyHub visibility only; it does not delete collections or change Jellyfin's own permissions or other clients.
- My list now includes **Saved favorites** from Jellyfin and **Requested by you** from Seerr, with independent pages, source tabs and a request-status filter. Seerr identity is verified by immutable Jellyfin user ID; both the upstream owner filter and each returned request owner are checked. A response containing another account's requests is withheld. Integration failures retain the other source's results.
- Request cards distinguish approval, requested/queued, processing, active downloading (with percentage when supplied), paused, importing, download issues, available/partial, declined and removed states. Current availability is verified against permitted Jellyfin items; “available in Seerr” does not grant Jellyfin access. An available standard-quality copy does not fulfill a 4K request. Watched/Watching/Unwatched labels and resume progress use that viewer's Jellyfin data; absent/deleted items show unknown watch status instead of inventing history.
